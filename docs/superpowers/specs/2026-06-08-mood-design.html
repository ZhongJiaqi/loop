§ 0 产品定位 · 为什么集成进 loop 但与 loop 主旋律隔离

核心需求：用户作为 INTJ，过去通过过度分析逃避感受。需要一个能"停下来命名感受、看见、让它过去"的空间。

张力：loop 的语义场是「做、塑造、推进」（Habits → Identity → Hall）；觉察空间需要的语义场是「停、看、不评价」。两套哲学若混居，互相稀释。

当前阶段决策：先在 loop 内做 MVP 体验（验证使用频率、使用场景、想要什么），未来拆产品时无痛搬走。功能层面命名 Mood（中性功能词），未来独立产品启用「看见」+「不分析，只看见」品牌叙事。

不做的事（明确边界）：

  • 不算「今日完成度」
  • 不触发 confetti / streak / Hall
  • 不跟 Affirmation / Habit 共用组件
  • 不显示在 Today 的 affirmation/habit list 旁边
  • 不加 note / 触发器关联 / 强度评级 — 任何一个都开过度分析回路的口子

§ 1 架构与文件组织

可拆性原则：所有 Mood 相关代码集中在自有模块，与 Affirmation/Habit 体系零耦合。未来拆产品 = 整组复制走。

src/
├── components/
│   ├── MoodView.tsx              # Mood tab 主视图（按天极简流水）
│   ├── MoodPickerSheet.tsx       # 选桶 + 选词的 bottom sheet
│   └── MoodEntryRow.tsx          # 单条记录行
├── lib/
│   └── moods.ts                  # 9 桶 canonical 数据（颜色 / 桶名 / 动机 / 词典）
├── types.ts                      # 追加 MoodBucketId / MoodEntry / MoodBucket
├── useMoodStore.ts               # 独立 hook，与 useStore.ts 解耦
└── App.tsx                       # 加第 4 tab（4 处轻量编辑）

"零复用"的边界：

  • 展示型组件（list / row / section / card / button 视觉）— 一律新写 Mood 自己的，不沿用 Affirmation/Habit 的视觉组件。这是可拆性的核心保障。
  • 手势 / 基础设施型组件（SwipeActions 的 swipe-to-reveal、NetworkStatusBanner、withTimeout）— 可复用。这些是跨业务的通用工具，未来拆产品时一并复制即可，不构成耦合。

export interface MoodEntry {
  id: string;                // Firestore doc id（auto）
  userId: string;
  bucket: MoodBucketId;      // 必填，9 选 1
  words: string[];           // 选的细分词，可为空数组（只记桶）
  createdAt: string;         // ISO 时间戳
  updatedAt?: string;        // 仅编辑后才有
}

Firestore 集合：users/{uid}/moods/{moodId}，与 microHabits / tasks 平级互不依赖。

security rules（追加到 firestore.rules）：

match /users/{userId}/moods/{moodId} {
  allow read, delete: if isOwner(userId);
  allow create: if isOwner(userId) &&
    request.resource.data.userId == userId &&
    request.resource.data.bucket in ['bukar','bitter','fear','greed','anger','pride','brave','accept','peace'] &&
    request.resource.data.words is list;
  allow update: if isOwner(userId) &&
    request.resource.data.userId == resource.data.userId; // userId 不可变
}

§ 3 9 桶 canonical 数据（src/lib/moods.ts）

这套数据是唯一真理源。词典按那张霍金斯能量层级表 OCR 整理，每桶用全集（30–100 个/桶）。MVP 不砍词——砍掉就破坏了「找到精准那个词」的命名训练核心价值。

export interface MoodBucket {
  id: MoodBucketId;
  zhName: string;        // "恐惧"
  motive: string;        // "想安全稳妥"（底层动机，对应图顶层）
  color: string;         // hex
  words: readonly string[];
}

颜色策略：低能量 → 高能量 = 冷暗紫灰 → 温亮天蓝。明确避开 loop 的米色 / 金色（loop 的"庆祝色"），让 Mood 自成视觉区。

4.5 日期格式约定

  • 当天 → "今天 · M/D Ddd"（如 "今天 · 6/8 Sat"）
  • 昨天 → "昨天 · M/D Ddd"
  • 前天 → "前天 · M/D Ddd"
  • 4+ 天前 → "M/D Ddd"（不带相对前缀）
  • 跨年时间戳 → "YYYY/M/D Ddd"
  • 时间格式 → "HH:mm"（24 小时制，与 loop 现有 date-fns format 风格一致）

§ 5 状态管理 · useMoodStore

独立 hook，不并入 useStore.ts。避免污染现有的 task 创建逻辑（2026-05-22 修过的 race condition 不能再碰）。

export function useMoodStore(userId: string | null) {
  const [entries, setEntries] = useState<MoodEntry[]>([]);
  const [loaded, setLoaded] = useState(false);

  useEffect(() => {
    if (!userId) return;
    const q = query(
      collection(db, `users/${userId}/moods`),
      orderBy('createdAt', 'desc')
    );
    return onSnapshot(q, (snap) => {
      setEntries(snap.docs.map(d => ({ id: d.id, ...d.data() } as MoodEntry)));
      setLoaded(true);
    });
  }, [userId]);

  const addMood = async (bucket: MoodBucketId, words: string[]) => {
    if (!userId) return;
    const ref = doc(collection(db, `users/${userId}/moods`));
    await withTimeout(
      setDoc(ref, { userId, bucket, words, createdAt: new Date().toISOString() }),
      10000, 'addMood'
    );
  };

  const updateMood = async (id: string, patch: Partial<Pick<MoodEntry,'bucket'|'words'>>) => {...};
  const deleteMood = async (id: string) => {...};

  return { entries, loaded, addMood, updateMood, deleteMood };
}

App.tsx 同时持有两个 hook：useStore(uid) 喂 Today/Practice/History，useMoodStore(uid) 喂 MoodView。两套数据流彼此不知道。

§ 7 错误处理 + 离线

  • 网络断：现有 NetworkStatusBanner 自动接管显示（Mood 共享底层基础设施）
  • 离线读写：Firestore persistentLocalCache 让 Mood 离线可读写，回线自动 sync
  • 超时：addMood / updateMood / deleteMood 全部 withTimeout(10000) 包装，沿用现有 src/lib/timeout.ts
  • 用户兜底：UI 用 try/finally 保证 saving 状态总会复位
